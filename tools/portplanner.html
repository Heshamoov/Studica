One global channel space. Studica addresses every peripheral from a
  single index range — dio pin: 15, servo port: 14,
  ultrasonic ping: 8 / echo: 9, sharp port: 22. So a
  servo on 14 and a DIO on 14 are treated as the same physical pin. This tool
  flags that; it is the most common bring-up mistake and the hardest to see
  on the bench.

  
One caveat, unresolved. Studica’s own working course project
  has studica::Servo servo{8} alongside START_BUTTON = 8,
  which suggests the servo header may be a separate space from DIO. That
  cannot be settled without the board in hand. The tool still warns — a
  false alarm costs a glance, a missed clash costs a run. Check the silkscreen;
  if servos really are separate, say so and the check can be relaxed.

  
Two different stacks — pick one. params.yaml + Python is the
  ROS 2 route via studica_control; its topic, message and service
  names are copied from Studica's own params_template.yaml and
  example nodes, so they are verified rather than guessed. C++/Java is the
  separate WPILib route using TitanQuad. They do not mix.

  
Note for this robot: ROS 2 is not installed on the test robot's image and
  the real program (robot-onboard/) is C++. Plan pins here, give each device a Robot role, then press Send to robot: the numbers are converted and written to the robot's settings (the same values you see on tools/settings.html). Channel numbers on this page are the board's own (FlexDIO 0-11, HiCurrDIO 12-21); every number is the one printed on the board and is sent as it is.
